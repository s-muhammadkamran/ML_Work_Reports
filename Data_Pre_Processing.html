We use the Fatal Police Shooting data to answer the questions given in this notebook.

Fatal Police Shooting Data¶

About dataset
The dataset consists of following columns

  1. id : unqiue identifier of each victim
  2. name : name of a victim
  3. date : date on fatal shooting
  4. manner_of_death : manner of death classification
    • Shot
    • Shot and Tasered
  5. armed : indicates that the victim was armed with some sort of implement that a police officer believed could inflict harm
    • undetermined: it is not known whether or not the victim had a weapon
    • unknown: the victim was armed, but it is not known what the object was
    • unarmed: the victim was not armed
  6. age : age of victim
  7. gender : the gender of the victim. The Post identifies victims by the gender they identify with if reports indicate that it differs from their biological sex.
    • M: Male
    • F: Female
    • None: Unknown
  8. race : race of victim
    • W: White, non-Hispanic
    • B: Black, non-Hispanic
    • A: Asian
    • N: Native American
    • H: Hispanic
    • O: Other
    • None: unknown
  9. city : the municipality where the fatal shooting took place. Note that in some cases this field may contain a county name if a more specific municipality is unavailable or unknown.
  10. state : two-letter postal code abbreviation
  11. signs_of_mental_illness : News reports have indicated the victim had a history of mental health issues, expressed suicidal intentions or was experiencing mental distress at the time of the shooting.
  12. threat_level : These would include incidents where officers or others were shot at, threatened with a gun, attacked with other weapons or physical force, etc. The attack category is meant to flag the highest level of threat. The other and undetermined categories represent all remaining cases. Other includes many incidents where officers or others faced significant threats.
  13. flee : News reports have indicated the victim was moving away from officers
    • Foot
    • Car
    • Not fleeing
  14. body_camera : News reports have indicated an officer was wearing a body camera and it may have recorded some portion of the incident.

As per the question format and the explanation given in FAQs, we are required to remove the outliers from df['age'] columns only and save the values to df['age'] again. np.clip infact normalize the outlier within a given lower and upper bound. Using np.clip will overcome the issue of having nulls in the age column if we otherwise choose to drop the outliers entries. Below example code we have 2 other options to handle the outliers with certain consequences. Droping only values from age column will introduce nulls in this field and removing the whole rows of outliers will cause data loss for other attributes. Hence np.clip is a better option but it'll introduce biaseness in data.¶

id: The id column is a unique identifier for each row, but it has no impact on our current KDD excercise. Since each value is unique, it doesn’t provide any meaningful pattern or trend that could help in predictions. Including it would only add noise to the model.

name: The name column is typically a text field that uniquely identifies individuals or entities but does not provide generalizable information useful for extracting patterns.

date: The date column might contain temporal information, but in many cases, it can be decomposed into more relevant features (e.g., day, month, year). If the exact date itself is not relevant for the model, it can be excluded. Since we already extracted day, month and year, we can get rid of date column.

Dropping these columns simplifies the dataset, reduces dimensionality, and helps focus the model on features that are more likely to provide predictive insights.
